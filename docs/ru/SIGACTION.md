# struct sigaction

`struct sigaction` описывает, что делать, когда процессу приходит сигнал: какую функцию вызвать, какие ещё сигналы на это время заблокировать и с какими флагами. В ft_malcolm её заполняет `setup_signals` в `srcs/signal_handler.c` и передаёт в `sigaction` для `SIGINT` и `SIGTERM`.

Тип и функция объявлены в `<signal.h>`. Своего определения в проекте нет.

## 1. Зачем структура

Сигнал — короткое уведомление процессу от ядра: пользователь нажал Ctrl+C, другая программа вызвала `kill`, или сам процесс получил сигнал от системы. У каждого номера есть действие по умолчанию. У `SIGINT` и `SIGTERM` это немедленное завершение процесса.

Пока `ft_malcolm` блокируется в `recvfrom`, такое завершение закрыло бы процесс без строки `Exiting program...` и без `close` сокета. `sigaction` подменяет действие по умолчанию: ядро вызывает функцию программы, а та только ставит флаг. Выйти решает обычный код, когда снова получает управление.

`signal` делает похожую подмену одной функцией, но набор флагов и маску через него не задать. Проект использует `sigaction`.

## 2. Вызов sigaction

```c
int sigaction(int signum, const struct sigaction *act, struct sigaction *oldact);
```

| Аргумент | Что значит |
|----------|------------|
| `signum` | номер сигнала. В проекте это `SIGINT` или `SIGTERM` |
| `act` | новое поведение. Указатель на заполненную `struct sigaction` |
| `oldact` | куда записать прежнее поведение. Проекту оно не нужно, поэтому `NULL` |

Успех — `0`. Ошибка — `-1`, причина в `errno`. `setup_signals` печатает её через `strerror` и возвращает `-1`. `main` после этого выходит с кодом `1`, сокет ещё не открыт.

`SIGKILL` и `SIGSTOP` перехватить нельзя. `sigaction` для них вернёт ошибку. Проект их не ставит.

Один и тот же `sa` передаётся дважды: сначала для `SIGINT`, затем для `SIGTERM`. Оба сигнала зовут одну функцию.

## 3. Поля

На Linux структура выглядит так. `sa_handler` и `sa_sigaction` лежат в одном union: это два имени одной и той же памяти.

```c
struct sigaction {
    union {
        void (*sa_handler)(int);
        void (*sa_sigaction)(int, siginfo_t *, void *);
    } __sigaction_handler;
#define sa_handler   __sigaction_handler.sa_handler
#define sa_sigaction __sigaction_handler.sa_sigaction
    sigset_t sa_mask;                  /* доп. сигналы, блокируемые в обработчике */
    int      sa_flags;                 /* флаги поведения */
    void   (*sa_restorer)(void);       /* не для программы; выставляет libc */
};
```

| Поле | Тип | Что лежит |
|------|-----|-----------|
| `sa_handler` | `void (*)(int)` | функция на один аргумент — номер сигнала. Либо особые значения `SIG_DFL` и `SIG_IGN` |
| `sa_sigaction` | `void (*)(int, siginfo_t *, void *)` | другая форма того же union. Её читают, только если в `sa_flags` стоит `SA_SIGINFO` |
| `sa_mask` | `sigset_t` | сигналы, которые ядро дополнительно блокирует, пока выполняется обработчик |
| `sa_flags` | `int` | биты поведения. `0` — ни один флаг не включён |
| `sa_restorer` | `void (*)(void)` | служебный адрес возврата из обработчика. POSIX его не описывает, программа его не заполняет |

ft_malcolm пишет два поля: `sa_handler` и `sa_flags`. Остальное обнуляет `ft_bzero`.

## 4. sa_handler и sa_sigaction

В union помещается только одно из двух. Запись в `sa_handler` затирает `sa_sigaction`, и наоборот.

`sa_handler` используют без флага `SA_SIGINFO`. Ядро вызывает функцию и передаёт номер сигнала:

```c
static void sig_handler(int sig)
{
    (void)sig;
    g_running = 0;
}
```

`sig` здесь равен `SIGINT` или `SIGTERM`. Проект номер не различает: оба должны остановить цикл. `(void)sig` глушит предупреждение о неиспользуемом аргументе.

У `sa_handler` есть два особых значения, это не адреса функций программы:

| Значение | Смысл |
|----------|--------|
| `SIG_DFL` | вернуть действие по умолчанию. Для этих двух сигналов — завершить процесс |
| `SIG_IGN` | игнорировать сигнал |

`sa_sigaction` — обработчик с тремя аргументами: номер, `siginfo_t *` (кто послал, какой код) и контекст. Он работает только вместе с `SA_SIGINFO`. Проект этот флаг не ставит и поле не заполняет.

---

## 5. sa_mask

`sa_mask` — набор номеров сигналов. Пока выполняется обработчик, ядро не доставляет сигналы из этого набора. Они ждут и приходят после возврата из функции.

Пустой набор значит: дополнительных блокировок нет. `ft_bzero(&sa, sizeof(sa))` обнуляет и это поле. На Linux нулевой `sigset_t` и есть пустой набор. Отдельный вызов `sigemptyset(&sa.sa_mask)` делает то же самое явно.

Пойманный сигнал ядро блокирует само, даже если его нет в `sa_mask`. Пока `sig_handler` работает из-за `SIGINT`, второй `SIGINT` не войдёт в функцию повторно. Снять это можно флагом `SA_NODEFER`. В проекте его нет.

`SIGTERM` в маске обработчика `SIGINT` тоже не указан, поэтому он может прервать обработчик `SIGINT`. Для этого кода это безопасно: обе функции делают одно присваивание `g_running = 0`.

---

## 6. sa_flags

Целое число, каждый бит включает отдельное поведение. Проект пишет `0`.

Флаги, без которых этот ноль понятен:

| Флаг | Если включён | При `sa_flags == 0` |
|------|----------------|---------------------|
| `SA_RESTART` | ядро само перезапускает прерванный `recvfrom` | `recvfrom` возвращает `-1`, `errno` равен `EINTR` |
| `SA_SIGINFO` | вызывается `sa_sigaction`, а не `sa_handler` | вызывается `sa_handler` |
| `SA_NODEFER` | текущий сигнал не блокируется на время обработчика | блокируется |
| `SA_RESETHAND` | после первого срабатывания действие снова `SIG_DFL` | обработчик остаётся, пока процесс жив |

`SA_RESTART` здесь нельзя включать. С ним Ctrl+C во время `recvfrom` не возвращает управление в цикл: вызов просто продолжается, и `g_running == 0` проверяется только после следующего кадра.

## 7. Как это собрано в ft_malcolm

`main` вызывает `setup_signals` после разбора аргументов и до поиска интерфейса:

```c
struct sigaction sa;

ft_bzero(&sa, sizeof(sa));
sa.sa_handler = sig_handler;
sa.sa_flags = 0;
sigaction(SIGINT, &sa, NULL);
sigaction(SIGTERM, &sa, NULL);
```

После `ft_bzero` и двух присваиваний структура такая:

| Поле | Значение |
|------|----------|
| `sa_handler` | `sig_handler` |
| `sa_sigaction` | та же память, отдельно не используется |
| `sa_mask` | пустой набор |
| `sa_flags` | `0` |
| `sa_restorer` | `NULL` в структуре программы. Обёртка libc перед системным вызовом подставляет свой адрес |

Флаг выхода объявлен в `srcs/main.c` и виден остальным файлам через `extern` в `includes/ft_malcolm.h`:

```c
volatile sig_atomic_t g_running = 1;
```

`1` — работать. Обработчик пишет `0`. Циклы в `main` и в `listen_arp_request` крутятся, пока значение равно `1`.

## 8. Почему recvfrom возвращает EINTR

`listen_arp_request` блокируется здесь:

```c
while (g_running)
{
    len = recvfrom(ctx->sockfd, buf, sizeof(buf), 0, NULL, NULL);
    if (len < 0)
    {
        if (errno == EINTR)
            continue;
        /* другая ошибка: сообщение и return -1 */
    }
    /* разбор кадра */
}
return (-1);
```

Ctrl+C в этот момент:

1. Ядро прерывает `recvfrom` и вызывает `sig_handler`.
2. Обработчик ставит `g_running = 0` и возвращается.
3. `recvfrom` возвращает `-1`, `errno` равен `EINTR`, потому что `SA_RESTART` нет.
4. `continue` возвращает к условию `while`. Условие уже ложно.
5. Функция возвращает `-1`.
6. `main` видит ошибку и `g_running == 0`, печатает `Exiting program...`, закрывает сокет и выходит с кодом `0`.

Если `EINTR` пришёл, а флаг всё ещё `1`, `continue` снова вызывает `recvfrom`. Так отсекается прерывание, после которого выходить не нужно.

## 9. Что обработчик имеет право делать

Обработчик может вызваться в середине любого вызова. Большая часть libc в этот момент небезопасна: `printf`, `malloc`, `strerror` оттуда звать нельзя.

Присваивание в `volatile sig_atomic_t` разрешено. `sig_atomic_t` читается и пишется одним действием, `volatile` запрещает компилятору держать значение только в регистре и не перечитывать его в цикле. Поэтому обработчик ограничивается `g_running = 0`, а печать и `close` остаются в `main`.

## 10. Команды

Номера сигналов:

```bash
kill -l
```

`SIGINT` — 2, его шлёт Ctrl+C в терминале, где запущена программа. `SIGTERM` — 15, его шлёт `kill` без имени сигнала.

Остановить уже запущенный процесс, подставив его pid:

```bash
kill -INT <pid>
kill -TERM <pid>
```

Оба варианта должны напечатать `Exiting program...` и выйти с кодом `0`, а не оборвать процесс молча. `kill -KILL` перехватить нельзя: процесс завершится сразу, без этой строки.

Описание полей и флагов:

```bash
man 2 sigaction
man 7 signal
```
