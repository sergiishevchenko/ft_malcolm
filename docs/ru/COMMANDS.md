# Команды для проверки ft_malcolm

Лист команд для этой лаборатории. Ожидаемый вывод и пояснения — в [EVALUATION.md](EVALUATION.md).

| | Атакующий | Цель |
|--|-----------|------|
| IP | `192.168.65.14` | `192.168.65.15` |
| MAC | `aa:77:fb:2e:e0:ed` | `aa:77:fb:2e:e0:aa` |
| Интерфейс | `enp0s1` | `enp0s1` |

Подменяемый MAC в аргументах — `de:ad:be:ef:00:01`, не настоящий MAC атакующего.

Команды ниже помечены, на какой машине их запускать. Там, где нужен второй терминал атакующего, это написано в заголовке шага.

---

## 1. Ограничения задания

На атакующем, после `make`.

В бинарнике один глобал: `g_running`.

```bash
nm ft_malcolm | grep ' [BbDd] ' | grep -v __
```

Внешние функции сверяют со списком из задания.

```bash
nm -u ft_malcolm | sort
```

Юнит-тесты IP, MAC и парсинга. Root не нужен.

```bash
make test
```

---

## 2. Ошибки ввода

На атакующем. Каждая команда сразу завершается.

Нет аргументов, печатает usage.

```bash
sudo ./ft_malcolm
```

Мусор вместо аргументов.

```bash
sudo ./ft_malcolm a
sudo ./ft_malcolm a b c
```

Аргументов больше четырёх.

```bash
sudo ./ft_malcolm a b c d e f
```

Пустые строки.

```bash
sudo ./ft_malcolm "" "" "" ""
```

Неизвестный флаг.

```bash
sudo ./ft_malcolm --unknown 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Без root: `must be run as root`.

```bash
./ft_malcolm 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Один, два и три аргумента вместо четырёх.

```bash
sudo ./ft_malcolm 192.168.65.14
sudo ./ft_malcolm 192.168.65.14 de:ad:be:ef:00:01
sudo ./ft_malcolm 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15
```

Октет IP больше 255.

```bash
sudo ./ft_malcolm 10.11.11.1111 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

IP целиком невалидный.

```bash
sudo ./ft_malcolm 999.999.999.999 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Target IP не адрес и не имя хоста.

```bash
sudo ./ft_malcolm 192.168.65.14 de:ad:be:ef:00:01 abc.def.ghi.jkl aa:77:fb:2e:e0:aa
```

В MAC три символа в первом байте.

```bash
sudo ./ft_malcolm 192.168.65.14 aaa:bb:cc:dd:ee:ff 192.168.65.15 aa:77:fb:2e:e0:aa
```

В MAC пять байт вместо шести.

```bash
sudo ./ft_malcolm 192.168.65.14 aa:bb:cc:dd:ee 192.168.65.15 aa:77:fb:2e:e0:aa
```

В MAC нешестнадцатеричный символ.

```bash
sudo ./ft_malcolm 192.168.65.14 zz:bb:cc:dd:ee:ff 192.168.65.15 aa:77:fb:2e:e0:aa
```

MAC через дефис. Нужен формат с двоеточиями.

```bash
sudo ./ft_malcolm 192.168.65.14 aa-bb-cc-dd-ee-ff 192.168.65.15 aa:77:fb:2e:e0:aa
```

## 3. Один поддельный ответ

Атакующий, второй терминал: смотреть ARP на проводе.

```bash
sudo tcpdump -i enp0s1 -n arp
```

Атакующий, первый терминал: ждать запрос «кто имеет `192.168.65.14`» от `192.168.65.15`.

```bash
sudo ./ft_malcolm 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Цель: один ARP-запрос к подменяемому адресу. Программа ответит и сама выйдет.

```bash
arping -c 1 -I enp0s1 192.168.65.14
```

---

## 4. Запись в ARP-таблице цели

Атакующий: отвечать на каждый подходящий запрос, пока не нажмёшь Ctrl+C.

```bash
sudo ./ft_malcolm -c 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Цель, пока процесс ещё слушает: ядро само спрашивает MAC и создаёт запись.

```bash
ping -c 1 -W 1 192.168.65.14
```

В строке должен быть `lladdr de:ad:be:ef:00:01`. Если `aa:77:fb:2e:e0:ed` — повтори ping. Затем Ctrl+C на атакующем.

```bash
ip neigh show 192.168.65.14
```

---

## 5. Чужой ARP игнорируется

Атакующий: снова ждать только запрос от цели про `192.168.65.14`.

```bash
sudo ./ft_malcolm 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Цель: запрос про другой IP. Программа молчит.

```bash
arping -c 3 -I enp0s1 192.168.65.99
```

Цель: запрос про нужный IP. Программа отвечает и завершается.

```bash
arping -c 1 -I enp0s1 192.168.65.14
```

---

## 6. Ctrl+C и SIGTERM

На атакующем.

Запустить и нажать Ctrl+C: выход с текстом `Exiting program...`.

```bash
sudo ./ft_malcolm 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Второй терминал: запустить в фоне.

```bash
sudo ./ft_malcolm 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa &
```

Послать SIGTERM последнему фоновому процессу.

```bash
kill $!
```

## 7. Десятичный IP и hostname

На атакующем. Первые четыре стартуют и ждут запрос — останови Ctrl+C. Последняя завершается сама.

`3232252174` — это `192.168.65.14` одним числом.

```bash
sudo ./ft_malcolm 3232252174 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

`3232252175` — это `192.168.65.15` одним числом.

```bash
sudo ./ft_malcolm 192.168.65.14 de:ad:be:ef:00:01 3232252175 aa:77:fb:2e:e0:aa
```

Имя `localhost` резолвится в `127.0.0.1`.

```bash
sudo ./ft_malcolm localhost de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Имя этой машины подставляется как target IP.

```bash
sudo ./ft_malcolm 192.168.65.14 de:ad:be:ef:00:01 $(hostname) aa:77:fb:2e:e0:aa
```

Несуществующее имя, ошибка `unknown host`.

```bash
sudo ./ft_malcolm 192.168.65.14 de:ad:be:ef:00:01 nonexistent.invalid.host aa:77:fb:2e:e0:aa
```

## 8. Verbose

Атакующий: подробный разбор каждого принятого и отправленного ARP.

```bash
sudo ./ft_malcolm -v 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Цель: один запрос. Программа печатает дамп, отвечает и выходит.

```bash
arping -c 1 -I enp0s1 192.168.65.14
```

Атакующий: то же для длинного флага, затем снова `arping` на цели.

```bash
sudo ./ft_malcolm --verbose 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

## 9. Continuous

Атакующий: не выходить после первого ответа.

```bash
sudo ./ft_malcolm -c 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Цель: пять запросов, на атакующем пять ответов, затем Ctrl+C.

```bash
arping -c 5 -I enp0s1 192.168.65.14
```

Атакующий: длинная форма, тот же `arping` на цели, затем Ctrl+C.

```bash
sudo ./ft_malcolm --continuous 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

## 10. Gratuitous

Цель: создать запись соседа. В ней будет настоящий MAC `aa:77:fb:2e:e0:ed`.

```bash
ping -c 1 -W 1 192.168.65.14
ip neigh show 192.168.65.14
```

Атакующий, второй терминал: увидеть broadcast reply.

```bash
sudo tcpdump -i enp0s1 -n -e arp
```

Атакующий: объявить сети «`192.168.65.14` теперь `de:ad:be:ef:00:01`» и сразу выйти.

```bash
sudo ./ft_malcolm -g 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Цель, сразу, без нового ping: MAC должен смениться на `de:ad:be:ef:00:01`.

```bash
ip neigh show 192.168.65.14
```

Атакующий: тот же broadcast плюс hex-дамп. Сама завершается.

```bash
sudo ./ft_malcolm -v -g 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Атакующий: длинная форма `-g`. Сама завершается.

```bash
sudo ./ft_malcolm --gratuitous 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

## 11. Выбор интерфейса

На атакующем.

Список интерфейсов. Рабочий здесь — `enp0s1`.

```bash
ip link show
```

Слушать только `enp0s1`. Ждёт запрос — останови Ctrl+C.

```bash
sudo ./ft_malcolm -i enp0s1 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Интерфейса нет, ошибка `could not get interface info`.

```bash
sudo ./ft_malcolm -i nonexistent0 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Флаг `-i` без имени интерфейса.

```bash
sudo ./ft_malcolm -i
```

---

## 12. Все флаги вместе

Атакующий: verbose, непрерывный режим и явный интерфейс. До первого ARP видна только строка про `enp0s1`.

```bash
sudo ./ft_malcolm -v -c -i enp0s1 192.168.65.14 de:ad:be:ef:00:01 192.168.65.15 aa:77:fb:2e:e0:aa
```

Цель: два запроса, два дампа и два ответа. Процесс остаётся — Ctrl+C на атакующем.

```bash
arping -c 2 -I enp0s1 192.168.65.14
```
